# 原站测评嵌套与钉钉回传服务

独立项目：`/home/it01/code/bigfive-open-nesting`，Windows 路径 `\\wsl.localhost\Ubuntu-26.04\home\it01\code\bigfive-open-nesting`。

打开本服务 → 在页面内完成 `https://bigfivepersonality.me/zh` 的原站测评 → 查看原站报告 → 后端读取原站五维整数分数 → 自动写入指定钉钉 AI 表格。

按最新要求，**不使用数据库**。已按用户授权复用现有 `bigfive-open` 的钉钉应用与 AI 表格，将五项钉钉配置单独保存到本项目后端 `.env`；不修改原项目配置、数据库或服务。「人格类型」单选字段记录原站中文报告中的类型名称，例如「探索家」「温柔智者」；「描述」富文本字段记录类型名下方的特征短句与正文。

## 人事登记与专属邀请

当前默认入口为人事登录/登记页。使用现有应用完成钉钉 OAuth 登录；不再额外校验企业成员、在职状态或所属部门，也不需要 CorpId。登录后卡片左上角显示钉钉头像与昵称，头像缺失或加载失败时显示姓名首字。已有旧登录缓存若没有头像，退出后重新登录即可获取。详见 [钉钉登录配置指引](docs/dingtalk-login-setup.md)。

人事登记纯中文汉字姓名（不能包含任何空格、字母、数字或符号）和中国大陆11位手机号（均必填，手机号支持 +86）后，生成完整、唯一的 `/i#随机加密令牌` 链接。令牌和本地暂存联系人采用 AES-256-GCM 加密，有效期从生成开始72小时；来访者不需要登录或再填资料。仅打开链接不消耗测评；开始后绑定原浏览器，未完成时可刷新继续。不同邀请的原站答案缓存相互隔离。

生成链接时，先将姓名和电话写入钉钉，由钉钉自动生成「写入时间」，确认成功后才显示链接。每次独立登记使用不同 UUID；首次新增前加密记录已存在的匹配行 ID，回执丢失时排除旧行恢复本次新增行；响应丢失或重复点击重试沿用原 UUID/clientToken，避免重复建行。钉钉暂时不可用时返回待处理状态，页面自动查询、后台持久重试，刷新页面可继续查询原请求。

原站正式报告生成后，后端分页查询钉钉中姓名、电话都完全相同的记录，选择「写入时间」最大的那一行，仅更新五维分数、人格类型、描述和原站报告链接。选定行 ID 和首次结果字段快照持久保存，后续重试固定更新这一行，不再新建结果记录，也不覆盖姓名、电话或写入时间。「更新时间」由钉钉自动维护，本服务不发送该字段。若没有匹配行、匹配行写入时间无效或最新时间并列，保留任务等待处理，避免误写其他行。当前结果页可继续查看；完成后关闭或刷新入口失效。后台同步不依赖页面保持打开；失败继续重试，钉钉记录保留。每个邀请只对应一份独立测评。按当前匹配规则，同一姓名和电话再次登记后，较早邀请后完成的测评也会更新该联系人最新登记行。`HR_PORTAL_ENABLED=false` 可用于开发时的旧匿名入口兼容，正式部署保持 true。

无数据库：增加的邀请、访问和登录会话均为受保护的持久文件。同步成功后移除本地暂存联系人和字段快照，保留最低去重回执；不要删除任务卷和 session.key，密钥丢失后旧链接及加密任务无法解密。

## 本机运行

需要 Node.js 24.10+（推荐 24 LTS）或 Docker Compose。

```bash
cp .env.example .env
npm ci
npm start
```

访问 <http://localhost:8082>。WSL 如未自动加载 Node，请先将 `/home/it01/.nvm/versions/node/v24.22.0/bin` 加入 PATH。

推荐使用独立 Docker 服务：

```bash
docker compose up -d --build
docker compose logs --tail=50
docker compose ps
```

- Compose 项目名 `bigfive-nesting-v2`，端口 `127.0.0.1:8082`，任务卷 `bigfive-nesting-v2_nesting-tasks`。
- 旧的 `bigfive-open` 服务及其数据卷不变；原来占用 8081 的嵌套容器也不由本项目启动/删除。
- `.env` 更改后执行 `docker compose up -d --force-recreate`；只用 `restart` 不会重新载入环境变量。
- 默认仅允许本机访问。对外使用独立域名反向代理，参考 `deploy/nginx.conf.example`，设置 `PUBLIC_ORIGIN=https://你的域名`、`COOKIE_SECURE=true`。花生壳在外层终止 HTTPS 时也必须填写实际外网 HTTPS 地址；服务不盲目信任转发头。
- Docker 本机任务卷与直接 `npm start` 的 `./data/` 相互独立。

## 花生壳外网访问

当前外网入口：<https://11ovwy9445440.vicp.fun/>，花生壳转发到本机8082。后端配置：

```dotenv
PUBLIC_ORIGIN=https://11ovwy9445440.vicp.fun
ADDITIONAL_ORIGINS=http://localhost:8082,http://127.0.0.1:8082
COOKIE_SECURE=true
```

外网入口使用 Secure、HttpOnly 会话 Cookie；明确列出的 HTTP 本机入口继续使用普通 HttpOnly Cookie。`ADDITIONAL_ORIGINS` 只接受完整网址、逗号分隔，必须同时设置 `PUBLIC_ORIGIN`，不支持通配符。更换花生壳域名后更新配置并执行 `docker compose up -d --force-recreate`。来源不匹配时提交返回403，原站可能转入不包含正式类型的本地备用结果，此时不会写入钉钉。

## 自动作答测试

在项目目录运行：

```bash
npm run test:assessment -- --url https://11ovwy9445440.vicp.fun --submit --expect-sync
```

新版门户下需要提供人事生成的邀请：

```bash
npm run test:assessment -- --url https://11ovwy9445440.vicp.fun --invite-url "完整邀请链接" --submit --expect-sync
```

不带邀请的旧命令仅适用于关闭门户的开发服务。脚本打开独立 Edge 浏览器会话，先检查域名、会话与提交来源，再自动开始原站50题测评，每题独立、等概率随机选择五个答案之一，每题真实等待3秒；正常约3分钟完成。`--submit` 会提交一次正式原站测评，并使用目标服务已有的钉钉配置更新该联系人最新登记行的结果；`--expect-sync` 等待钉钉确认，等待/失败不会被标成成功。脚本不会清理用户现有浏览器答案、改动题库、直接填入缓存或伪造时间。测试记录分数仅供联调，不能代表真实人格。

- 去掉 `--submit`：只走作答过程，不提交报告，不回传；完成后保存截图并关闭测试浏览器。
- 添加 `--headless`：后台运行。`--delay-ms 4000` 可放慢作答，不允许少于3000毫秒。原站限流或其他拒绝仍原样生效，不会自动重新提交。
- 每次运行证据位于 `test-results/assessment-日期时间/summary.json` 与 `page.png`，包括原站结果链接、类型、五维分数和回传状态。
- WSL 下自动复用本机 Codex 随附的 Windows Node、Playwright 与 Edge；其他机器需可用的 Node、Playwright 和 Edge。可以通过 `PLAYWRIGHT_MODULE` 指定 Playwright 模块，或 `PLAYWRIGHT_CHANNEL` 指定可用的浏览器通道。
- 本项目开发验证使用独立服务端口18082与 `test-results/` 任务目录；不向生产任务卷写入测试提交。用户对8082/外网运行 `--submit` 时会在目标服务产生真实记录。
- 写入钉钉的测试记录默认保留，便于查看核验，只有用户明确要求时才删除；本地任务暂存仍在同步成功后按原规则移除。

## 钉钉配置

原 AI 表格使用以下字段，名称可通过 `DINGTALK_FIELD_MAP` 修改。「写入时间」使用钉钉自动创建时间字段（createdTime），「更新时间」使用自动最后修改时间字段（lastModifiedTime）；本服务均不发送这两个字段。

| 字段名 | 类型 | 值 |
| --- | --- | --- |
| 姓名 | 文本 | 人事登记的姓名 |
| 电话 | 电话 | 校验并规范化的手机号 |
| 开放性 | 数字，百分比 | 原站 O 整数分数 ÷ 100，例如 42 分写入 0.42，显示 42% |
| 尽责性 | 数字，百分比 | 原站 C 整数分数 ÷ 100，例如 42 分写入 0.42，显示 42% |
| 外向性 | 数字，百分比 | 原站 E 整数分数 ÷ 100，例如 42 分写入 0.42，显示 42% |
| 宜人性 | 数字，百分比 | 原站 A 整数分数 ÷ 100，例如 42 分写入 0.42，显示 42% |
| 神经质 | 数字，百分比 | 原站 N 整数分数 ÷ 100，例如 42 分写入 0.42，显示 42% |
| 人格类型 | 单选 | 原站中文报告的类型名称，缺少的选项由服务自动补齐，钉钉生成选项 ID |
| 描述 | 富文本 | `{markdown: 原站描述}`，类型标题下方的特征短句和正文，保留段落 |
| 链接 | 链接 | `https://bigfivepersonality.me/zh/r/原站ID` |
| 写入时间 | 创建时间 | 钉钉自动生成；查询最新登记时读取，不由服务赋值 |
| 更新时间 | 最后修改时间 | 钉钉自动维护，服务不发送 |

在后端 `.env` 填写：

```dotenv
DINGTALK_APP_KEY=
DINGTALK_APP_SECRET=
DINGTALK_BASE_ID=
DINGTALK_SHEET_ID_OR_NAME=
DINGTALK_OPERATOR_ID=
```

`BASE_ID` 是 AI 表格文档 nodeId；`SHEET_ID_OR_NAME` 是其中一张数据表的 ID 或名称；`OPERATOR_ID` 是有编辑权限操作人的 **unionId**，不是 userId。应用需开通 `Notable.Base.Write.All` 和 `Notable.Base.Read.All`，并能访问该表。重复令牌的恢复需要读取权限。

凭据全部留空允许启动，暂不投递；只填一部分则拒绝启动，避免错误配置被当作可用回传。凭据不进入页面、浏览器脚本或日志。不要将 `.env` 提交到版本控制。

单选字段按类型名称字符串写入，无需预先手工配置全部类型；结果更新前会读取当前单选选项；缺少原站类型时，保留已有选项及其 ID，追加该类型名称，并读回确认后再更新结果。读回的单选值通常为 `{id,name}`，重试恢复按名称核验；富文本描述按完整 Markdown 核验，仅容忍钉钉补加的末尾换行。

每个新任务首次投递前读取钉钉字段元数据：五维中格式为 `PERCENT` 的数字列写入 0–1 小数，普通数字列仍写入 0–100 整数；描述支持 `richText` 对象与普通文本。元数据获取失败、字段缺失或类型不兼容时保留任务重试。本地原站分数始终保持 0–100 整数，转换仅作用于首次生成的投递快照，后续重试直接复用。

字段别名示例（其他字段使用默认名称）：

```dotenv
DINGTALK_FIELD_MAP={"result_url":"原站结果链接"}
```

已有任务一旦尝试投递，就固定表格目标、字段快照和 clientToken；结果更新还固定已选中的钉钉记录 ID。更改表格目标后，旧任务报 `DingTalkTargetChanged` 并保留，不会默默写到另一张表。首次配置前积压的任务没有绑定目标，配置完成后自动处理。未尝试投递且缺少人格类型或描述的旧任务会补读原站报告；只有原分数和链接一致时补采类型与描述并继续，保持原时间和令牌。已存在旧投递快照的任务不会改写，保留并报 `LegacySnapshotNeedsReview`，避免改变可能已写入远端的内容。

## 原站代理与采集

外层 `/` 是本服务入口。iframe 加载同源 `/zh`，其页面、样式、图片、Next.js 脚本与 RSC 路由由固定原站反向代理提供。响应中的原站绝对地址改为服务地址，原站内部导航留在嵌套页面中。浏览器无需扩展或用户脚本。

仅增加一个在原站应用启动前加载的桥接脚本：为原站 `/api/results` POST 附加提交 ID，并向外层页面报告开始/提交状态。不改题库、答案、开始/结束时间、原站计分或原站错误响应。

后端先把原站成功返回的报告 ID/回执写入任务文件，再把响应传回浏览器。后台读取 `/zh/r/{id}` 的 Next.js Flight JSON，确认报告身份，读取 `scores.O/C/E/A/N.score`，严格要求五个 0–100 整数。人格类型读取同一报告组件中、绑定当前报告 ID 的 `title` 中文标题，不从分数重新分类或翻译英文标识。描述限定为匹配该类型 `h1` 标题后连续的原站段落（特征短句与正文），保留两段原文。缺少类型、描述或出现冲突时保留任务重试。不执行原站脚本，不从答案重新计算，也不从首页示例分数采集。结构变化时任务报错并重试，不写入猜测分数。

`npm run probe` 使用原站公开 `demo0001` 报告进行只读兼容性检查，不提交测评或写钉钉。

## 可靠性与本地数据

没有 SQLite、MySQL 或测评结果数据库，`data/` 只保存：

- `session.key`：服务会话签名密钥，重启后保持不变。
- `tasks/{submission UUID}.json`：原站回执、请求摘要、任务状态；待同步期间暂存五维分数、人格类型、描述与字段快照。
- `.service.lock/`：保证同一任务目录一次只有一个进程写入，异常退出后自动恢复。

每次状态更新先写临时文件、fsync，再原子 rename 并 fsync 目录。报告采集结果与投递任务在同一个 JSON 更新中保存。文件损坏时拒绝启动，避免静默丢弃待同步结果。

钉钉确认返回记录 ID 后移除本地暂存分数、人格类型、描述和字段快照，仅保留请求摘要、会话归属、原站回执、clientToken、远端记录 ID 等最小回执。回执用于重复请求保护和页面状态查询，不做本地历史报告查询。独立测评使用不同提交 ID，即使分数相同也分别投递；同一草稿的重试、并发请求和刷新不会新增第二条任务。原站明确拒绝时清除浏览器恢复指针；待同步、失败重试及提交状态不确定的任务继续后台查询，但不自动导航到旧报告。外层不显示任何顶部状态提示。已同步的提交会清除浏览器恢复指针，重新打开默认显示原站首页。点击原站开始测试入口时，若旧草稿已经完成，则清除原站 `resetTest` 对应的六项缓存并开始新测评；未完成草稿继续保留。

失败默认按 10、20、40、80、160、300 秒退避，此后每 300 秒继续重试，不因次数上限丢弃任务。钉钉成功但响应丢失时，使用相同 `clientToken` 重试；收到重复令牌错误后，核对远端原站链接、五个分数、人格类型、完整描述、两项时间，且仅唯一匹配时恢复记录 ID。重复令牌本身不视为成功。找不到记录或匹配冲突时继续保留并报错，不更换令牌再新增。

页面始终只展示原站内容，已完全移除外层顶部说明、提交进度、同步成功/失败提示与报告快捷链接。后台状态接口仍明确区分采集中、等待同步、失败重试与已同步；仅在取得钉钉记录 ID 后确认成功。状态查询继续用于清理已完成或被拒绝提交的恢复指针，不影响原站页面导航。

原站没有已确认的提交幂等接口。若原站响应丢失且无法取得报告 ID，本服务不盲目重发原站 POST；保留不确定回执，管理员可通过后台状态接口检查。原站明确拒绝（包括 429）时原样返回，不生成结果。原站可能显示它自己的本地备用报告，后台不会将其当作已回传报告。

## 部署与维护边界

- 原站在线可用性、页面/API 结构及报告保留期限由原站决定。本服务没有复制题库与报告，离线时无法开始原站测评；已采集的待投递分数仍可重试钉钉。
- 原站请求从服务器出口发出，其限流规则继续生效；多位用户可能共用一个出口额度。本服务不会伪造用户 IP 或绕过原站限制。
- 任务目录仅供单进程使用，不支持多个副本共用目录分布式投递。锁和持久文件依赖 Linux 本地文件系统语义，推荐在 WSL/Docker 命名卷中运行。
- 不要删除任务卷、`session.key` 或待同步文件；`docker compose down` 保留任务卷，`down -v` 会删除未回传任务与去重回执。
- 停机备份整个任务目录/卷，包含签名密钥和回执；不要只备份未同步文件。恢复时先停服务，保留文件属主和权限。
- 进程异常退出后，文件锁最多等待约 30 秒，任务租约最多约 60 秒恢复。正常停止会等待在途请求与后台投递。
- 如果完全不允许任何本地持久任务文件，则无法同时保证重启续传和跨重启去重；当前实现保留这些最小必要文件。
